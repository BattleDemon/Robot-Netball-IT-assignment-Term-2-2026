# Overview
The movement driver (GENERAL/movement.py) was completely reworked to improve robustness, integrate with Dexter’s State_Controller, fix turning logic, and switch the internal angle representation to radians. All changes were shaped by live review from both team members.

1. Error resilience – no more crashes on typos
What: Removed raise ValueError from pivot_angle() and pivot(). Invalid side strings now silently return.

Why: A mistyped side (e.g. "Left" instead of "LEFT") must never crash the robot. The robot simply ignores the command and continues.

Review feedback: Dexter and Hugo both insisted that human‑defined strings should never halt execution. (BattleDemon: “for robotics … you never want to raise an error”)

2. Fixed pivot direction – clockwise now consistent
What: Rewrote the motor direction logic in pivot_angle() so that positive angle always means clockwise, regardless of which wheel is braked.

Why: Previously pivot_angle("LEFT", +90) turned counter‑clockwise while the same call with "RIGHT" turned clockwise – a bug that would confuse all strategy code. Now the sign convention is uniform.

Review feedback: Dexter noted the absolute‑value loop needed attention; the entire sign block was reworked as a result.

3. Removed timed pivot method
What: Deleted pivot(pivot_side, speed, duration_sec). Only pivot_angle remains.

Why: The angle‑controlled version is always sufficient; a timed variant adds redundancy and potential confusion. (BattleDemon: “Extra pivot?”)

4. Pivot now relies on odometry thread – no manual heading override
What: pivot_angle no longer manually updates self.heading. It only resets encoder references after the move.

Why: The background odometry thread continuously integrates the robot’s position and heading, including the small arc the centre travels during a pivot. Manual override was causing double‑counting and drift.

Review feedback: Dexter questioned the heading override logic, which led to this simplification.

5. Added spin_angle – fast in‑place rotation
What: New method spin_angle(angle_rad, speed) rotates the robot around its centre by running wheels opposite directions.

Why: Needed for quick ball tracking (no lateral movement). pivot_angle is reserved for netball rule compliance after catching.

Review feedback: Implicitly requested by the need to separate ball‑searching turns from legal pivots.

6. Removed turn_angle
What: Deleted the old turn_angle method that previously delegated to pivot_angle.

Why: All higher‑level helpers now call spin_angle explicitly. This forces the strategy writer to choose the correct turn type.

Review feedback: Gabe noted it was “redundant” after the new turning system.

7. New method: reverse_drive_to_point
What: Added reverse_drive_to_point(target_x, target_y, speed) – the robot faces 180° away and backs toward the target.

Why: When the claw/arm is on the front, the robot can reverse into position without turning around.

Review feedback: Suggested during discussion as a needed movement primitive.

8. Integration with State_Controller
What: The driver now accepts a state_controller object and uses it as the single source of truth for foul state, ground colour, and robot pose.

Odometry loop pushes (x, y, heading) to the controller every cycle.

Foul and ground colour are only read from the controller – never written by the driver.

Removed all local foul flags, locks, and the signal_* methods.

Why: Prevents state mismatches between movement, communication, and the state machine. The driver becomes a pure listener.

Review feedback: Dexter repeatedly pointed out that the driver must not set foul state or ground colour; it should only read them. (BattleDemon: “you need to check if my state is foul”, “Hugo does this” – referring to foul reset). Hugo also contributed by removing the old signal_ground_colour and related blocks.

9. Removed gyro blending
What: Deleted the complementary filter that blended odometry and gyro heading.

Why: Simplified the odometry loop; gyro was not currently used. (If reintroduced, a radian‑based blend can be added.)

Review feedback: Dexter expressed confusion over the blending line during review, leading to its removal.

10. Switched internal heading to radians
What: self.heading is now stored in radians (0 to 2π). All internal calculations, turning methods, and field helpers use radians.

Why: The state controller and the rest of the team’s logic expect radians. Avoids constant conversion in high‑level code.

Review feedback: Implicitly approved through the removal of degree‑based heading updates and the final radian commit.

11. Robot config additions
What: robot_config.py now includes:

START_ATTACK_HEADING = pi (180° in radians)

START_DEFENCE_HEADING = 0.0

Unified hoop coordinates (HOOP_Y_ATTACK and HOOP_Y_DEFENCE both point to the single physical hoop at y=0).

Why: Ensures each robot knows the correct initial heading and the exact hoop location, crucial for field‑aware navigation.

12. General code cleanup
Removed obsolete conveyor references from comments.

Normalised all State_Controller checks after Dexter confirmed a controller is always present.

Removed redundant foul elapsed checks in the monitor loop (BattleDemon: “to get to this section of code foul will have elapsed”).
